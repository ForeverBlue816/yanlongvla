# EXPLANATIONS: every surprise with its cause shown by an experiment (GOAL 2026-11-01 v3)

Format per block: Observation / Hypotheses / Experiment per hypothesis / Result / Verdict (CONFIRMED cause, REFUTED, OPEN). A cause is CONFIRMED only if an intervention changes the outcome in the predicted direction or a measurement isolates it. Noise floor (item 0): see E0.

## E0. Noise floor of one row total (item 0)
- Observation: our FP and the mentor's FP both score 618/1000 and agree on 872 of 1000 units (64 each way), same seeds, GPU and kernels differ (G10).
- Hypotheses: (a) unit outcomes of the same model flip between runs on the same GPU type; (b) the flips come from the GPU or software stack, not from run-to-run noise.
- Experiments: `rr__fp` (FP second run, RTX PRO 6000 Blackwell) against our first FP run; `rr__qtip_w2` (QTIP second run, checkpoint rebuilt from `q/qtip_w2`) against its first run; both also against the mentor's FP.
- Result: FP rerun vs first FP run: 618 vs 618, 0 units flip. QTIP rerun vs first QTIP run: 572 vs 573, 1 unit flips (0 improvements, 1 regression). FP rerun vs the mentor's FP: 64 improvements, 64 regressions (as before).
- Kernel intervention (item 2.6, 200 units, FP, same GPU, only the SDPA attention kernel restricted): default 127/200; `math` kernel 124/200 with 23 units flipped against the default (10 up, 13 down); `efficient` kernel 127/200 with 28 units flipped (14 up, 14 down). The mentor's FP differs from ours on 30 of the same 200 units.
- Verdict: CONFIRMED. (1) Run-to-run noise on a fixed GPU and kernel is zero (0 and 1 flipped units of 1000). (2) Any tiny numerical change flips about 12 to 15% of the units: changing only the attention kernel flips 11.5% and 14% of the units, the same as the 15% between our FP and the mentor's FP. So the 64 + 64 flipped units against the mentor's FP are explained by a numerical difference of that size (GPU, kernel, library), not by a difference in the model or the protocol; that the mentor's stack differs in exactly the kernel is not shown and not needed. (3) Consequence for reading tables: the net count changes by only a few units under such a perturbation (+0, -3 of 200), but the binomial scale of the flips is sqrt(128) = 11 successes per 1000. A difference between two rows smaller than about 20 successes (2 points) is within what a numerical perturbation alone can produce; e.g. VPTQ 495 / 493 / 487 / 471 and QuIP# 0 sweeps 554 vs QTIP 573 are not distinguishable by this measure. Calibration-set sensitivity (item 1.6) is a further source and is not measured yet.

## E1. Plain GPTQ 2 bits collapses (0/1000): which component? (item 2.2, first part)
- Observation: plain GPTQ W2 scores 0/1000 with all components quantized; AQLM scores 401.
- Hypotheses: (a) the vision tower breaks it; (b) the language model; (c) the action head; (d) only the sum of all three.
- Experiment: FP everywhere except one component quantized with the method (200 units, every 5th unit; FP scores 127/200 on them).
- Result so far: plain GPTQ: vision only 0/200, language only 20/200, head only 120/200. AWQ: vision only 0/200, language only 18/200, head only 103/200. AQLM: vision only 121/200, language only 105/200, head only 119/200. QTIP (no collapse, for reference): vision 128, language 123, head 122.
- Finer vision cuts (plain GPTQ, vision only, 200 units, FP 127): blocks 0-11 together 1; blocks 12-23 + merger 122; blocks 0-3 alone 122; blocks 4-7 alone 126; blocks 8-11 alone 119. AQLM on blocks 0-11: 125.
- Reading: no single group of four blocks breaks the model, yet the three of them together do (1/200): the damage of plain GPTQ in the vision tower is cumulative over blocks (each group costs 1 to 8 successes alone, all three together cost nearly all). So the cause is not one layer or one block range but the sum of the per-layer errors through the tower (plain GPTQ puts about 5x the error of the working methods into every block, see TASK1 audit), crossing a threshold; this is a measurement of where it is not localized, not yet an intervention (a test that halves the error of all vision layers, for example GPTQ with MSE clipping on the vision tower only, would show the threshold).
- Intervention (vision tower only, rest FP, 200 units): plain GPTQ 0/200 -> GPTQ with MSE-searched clipping 117/200 (FP 127). Same layers, same Hessians, same bits except the clipping rule: the collapse goes when the per-layer error is reduced. Vision with act-order + MSE: 119/200. Language only: plain 20 -> MSE 104 -> act-order + MSE 112/200. Per-layer best (the main-row recipe): vision 118, language 120 of 127.
- Verdict: PARTLY CONFIRMED (vision): the vision tower alone removes all successes and the language model alone most of them; the action head alone costs 7 of 127. Language halves, plain GPTQ: layers 0-7 alone 72/200, layers 8-15 alone 80/200, both together (language only) 20/200: the same cumulative pattern as in the vision tower (each half loses about 40%, together 84%). AQLM halves: 126 and 116; QTIP layers 8-15: 121. Which layers inside them, and whether replacing those layers by a better method restores success (the intervention), is not shown yet (halves vision_a/b, lang_a/b, head_dit, head_vl queued). For the vision tower this is now CONFIRMED: the cause is the accumulated per-layer error of plain GPTQ's min/max grouping (not one layer or block), shown by the intervention 0 -> 117 with MSE clipping and by the cumulative block pattern. Language model: CONFIRMED the same way (plain 20, MSE 104, act-order + MSE 112 of 127); head: not a cause (120/200 alone).

## E2. Larger VPTQ codebooks have lower layer error but score lower: do they overfit the 256 calibration observations? (item 1.3)
- Observation: on the worst layers v6k4096 / v8k12288 have 45-47% lower calibration output error than v4k256 (vision fc2 0.0544 to 0.0306 / 0.0292), yet Plus 1000 is 458 (v6k3072) and 426 (v8k12288) against 495 for v4k256 (v6k4096, over budget, scores 535).
- Hypotheses: (a) the codebooks fit the 256 calibration observations and generalize worse; (b) the calibration error is the wrong error measure for success; (c) the structures that lower the error on a few layers raise it on others (v8k12288 up_proj +31%).
- Experiments: (a) output error on a held-out Hessian (64 observations from 37 episodes outside the calibration, noise seed 1) for v4k256 (base), v5k1024, v6k3072, v6k4096, v8k12288 on 8 backbone and 5 head layers; intervention: quantize the same layers with the Hessians of 1024 observations (the 256 plus 768 from 192 other episodes) and measure the held-out error again.
- Result: held-out error is 1 to 12% above the calibration error for every structure, and the same for v4k256 (e.g. vision fc2 0.0544 / 0.0558) and for v8k12288 (0.0292 / 0.0302); the one larger gap (head attn1.to_k 0.0264 / 0.0372, +41%) is the same for all structures. The ranking of the structures is the same on the held-out Hessian as on the calibration. Quantizing with 1024 observations changes the held-out error by less than 1% (up_proj base 0.0079 / 0.0079, v8k12288 0.0103 / 0.0103; fc2 v8k12288 0.0302 both).
- Verdict: (a) REFUTED: no overfitting is visible, and tripling the calibration set does nothing. (b)/(c) OPEN: the layers where large codebooks are worse (up_proj, gate_proj, vision fc1: v8k12288 +31%, +30%) and the missing success-versus-error relation are examined in E4 (item 2.4), which needs the all-layer errors of the rows; those are not available for the deleted VPTQ outputs.

## E3. GPTQ act-order alone collapses (0/50) although its layer errors are lower than plain GPTQ: is one layer to blame? (item 2.1)
- Observation: `gptq_actorder_w2` 0/50 in the sanity gate; mean layer output error 0.0166 vs 0.0247 for plain GPTQ, worse than plain on 10 of 432 layers, including `language_model.layers.2.mlp.down_proj` (outlier channel ~6000x).
- Hypotheses: (a) the outlier layer `language_model.layers.2.mlp.down_proj` breaks under act-order; (b) act-order breaks other layers; (c) act-order is fine and the failure is the plain-GPTQ collapse seen in E1.
- Experiments (200 units, FP = 127): (a-intervention) act-order everywhere, plain GPTQ on that one layer (`base_l2down`); (a-sufficiency) act-order on that one layer only, everything else FP (`l2down`); (b) act-order on the vision tower only / language only / head only (queued).
- Result so far: `base_l2down` 1/200 (the collapse stays when that layer is plain); `l2down` alone 130/200 (that layer under act-order is harmless).
- Component result (act-order on one component, rest FP, 200 units, FP 127): vision 12, language 37, head 127. So (b) holds: act-order breaks the vision tower and the language model, and leaves the head intact; the same pattern as plain GPTQ (E1: vision 0, language 20, head 120), only less severe.
- Intervention: act-order together with MSE clipping removes the act-order collapse (vision 12 -> 119, language 37 -> 112): act-order alone leaves the min/max grouping error that breaks the vision tower and language model; MSE-searched clipping is the part that matters.
- Verdict: (a) REFUTED: removing act-order from that layer does not remove the collapse (1/200), and act-order on it alone does not cause one (130/200). The cause lies in act-order applied to other layers; the component tests (b) decide which. OPEN until those finish. (8 Nov, audit A10: the component results are in this block: (b) holds for vision and language, and act-order + MSE removes the collapse; the verdict is (b) CONFIRMED.)

## E4. Is the loss on libero_10 (and elsewhere) a long-horizon effect? (GOAL v3 2.5, v4 item 3a; first measurement, 5 Nov 2026)
**Observation.** libero_10 is the suite with the largest loss for every row (for example VPTQ loses 66 of the 139 units FP solves there).
**Hypotheses.** H1: error accumulates over the rollout, so units that need more policy calls (FP's own episode length) are lost more often. H2: the long units are simply the harder tasks (grasp precision, clutter), and length plays no part.
**Experiment (CPU, existing per-unit files, `jobs/experiments/libero10_length.py`, table in `experiments/libero10_length.md`).** The units FP solves, split into terciles by FP's policy calls; per tercile the share the row loses.
**Result.** The loss rises with length in nearly every row and suite, for example QTIP on libero_spatial 4% / 15% / 39% (short / middle / long), QuIP# 10 sweeps on libero_10 30% / 31% / 59%, VPTQ on libero_10 41% / 43% / 61%. AQLM is high at every length on libero_10 (55% / 60% / 76%) and flat on libero_spatial (25% / 31% / 25%), so the pattern is not universal. Every lost unit ran to the step limit (a failure cannot end earlier).
**Verdict: OPEN.** This is a correlation. H1 and H2 are not separated, because FP's episode length differs between tasks and between units of one task. What would separate them: (a) within one base task, compare lost and kept units by length (needs the per-unit file joined with the base task, CPU, next); (b) the open-loop per-step action error of each row against FP on the same observations at early and late steps of a rollout (needs one checkpoint per row on a GPU, so it waits for scratch space); (c) an intervention that changes the horizon without changing the task, such as running FP with a smaller action chunk (n_action_steps 4) and checking whether FP itself loses units.

## E5. Does our 1% damping handicap AQLM through the outlier layer? (GOAL v4 4a; 5 Nov 2026)
**Observation.** At 1% damping AQLM's output error on `language_model.layers.2.mlp.down_proj` is 0.0135, about 100 times the undamped 0.00011 and the 0.1%-damped 0.00003 (`TASK1_METHOD_AUDIT.md`). AQLM is the weakest toolkit row on GR00T LIBERO (401/1000 against QTIP 573).
**Hypotheses.** H1: this layer is a main cause of AQLM's loss. H2: it is not (the other layers' errors dominate).
**Experiment (intervention).** The AQLM row with only that layer re-quantized at 0.1% damping (relative output error 1.5e-5), everything else unchanged, on the 200 units of the component tests (`mx__l2fix__aqlm_w2`), against the same 200 units of the main AQLM row. FP scores 127 on them.
**Result.** AQLM main 76/200, with the layer fixed 81/200 (+5; 13 units gained, 8 lost). The noise floor of E0 flips 11 to 15% of the units under a tiny numerical change, so +5 of 200 is inside it.
**Verdict: H1 REFUTED as a main cause.** The 1% damping is a real departure on that layer but fixing it does not move AQLM's success outside the noise; AQLM's gap to QTIP lies elsewhere (not yet located: AQLM halves of vision and language are 105 to 121 of 200 in E1, so no single component explains it either).

## E6. Is the Fractal FP gap to the model card on open_drawer and close_drawer noise? (v4 Task 5b; 5 Nov 2026)
**Observation.** Our FP scores 48/100 on `open_drawer` and 63/100 on `close_drawer`; the model card reports 65 and 69. Our settings are the README's (1 action step, 300 steps, 5 environments, 100 episodes, seed 7).
**Hypotheses.** H1: noise of 100 episodes. H2: a systematic difference between our setup and the card's (candidates: attention kernel, `flash_attn` is not installed here and the server falls back to SDPA; library versions; the card's seeds).
**Experiment.** The same FP model again: same seed (rerun), seeds 8 and 9, on both families.
**Result.** `open_drawer`: 48 (seed 7), 58 (same seed again, 101 episodes), 55 (seed 8), 51 (seed 9): mean 53, spread 10 points between runs. `close_drawer`: 63, 57 (seed 8), 62 (seed 9): mean 61. Pooled over the four `open_drawer` runs (400 episodes) the standard error is 2.5 points, so the card's 65 is about 5 standard errors above our mean; for `close_drawer` the card's 69 is about 3 above.
**Verdict: H1 REFUTED for these two families (run-to-run noise is 5 to 10 points per run but does not reach the card's value); H2 OPEN.** The next test would be an FP run with flash attention (needs the package built on the Blackwell GPU) or the card's exact seeds, which are not stated.

## E7. Does a lower layer error go with more successes? (GOAL v3 2.4, v4 item 5; first measurement, 5 Nov 2026)
**Observation.** For QTIP, QuIP# without sweeps and QuIP# with 10 sweeps (the three rows with a complete per-layer table, `experiments/layer_errors_tables/per_layer_output_error.csv`) the mean relative output error over the layers of a component, on the calibration Hessian:

| component | QTIP | QuIP# 0 sweeps | QuIP# 10 sweeps |
|---|---|---|---|
| vision (104 layers) | 0.0056 | 0.0075 | 0.0076 |
| language (112) | 0.0038 | 0.0049 | 0.0073 |
| action head (864 over 4 suites) | 0.0038 | 0.0051 | 0.0057 |
| Plus 1000 successes | 573 | 554 | 531 |

The order of the errors is the order of the successes in every component. With three points, and with 573 against 554 inside the noise floor of E0, this is a consistent ordering and not yet a relation: the held-out errors (E2, VPTQ structures) rank the rows like the calibration errors, so over-fitting does not break the ordering, and the VPTQ variants (v6k3072, v8k12288) that lower the error do not raise the success (458 and 426 against 495; corrected 8 Nov from "535 and 495", audit A10: 535 is the over-budget v6k4096), which is the case this item was opened for.
**Hypotheses.** H1: the layer error predicts success across methods (QTIP and QuIP# fit it). H2: it does not, because the error of a few layers or of one component matters more than the mean (E1 shows vision and language blocks accumulate the error, the head does not).
**Verdict: OPEN.** What would decide it: success of rows built from the same method at several error levels (VPTQ structures, GPTQ variants) against the mean error of the vision and language components only, with the head excluded, since E1 shows the head tolerates quantization; this needs the per-layer errors of the VPTQ and GPTQ variants, which exist for 5 to 8 layers only (the full tables were deleted with their outputs for scratch space).

## E8. Units FP fails but quantized rows solve (Task 6c, rigour C4)
- Observation: of the 382 Plus 1000 units our GR00T FP fails, QTIP solves 72, QuIP# 81 and 76, VPTQ 68, GPTQ best 75, AQLM 49 (`experiments/rigour_v5/c4_units.md`); 9 units are solved by all five main rows (0.1 expected if independent).
- Hypotheses: (a) quantization helps some units (a regularizing effect); (b) these are FP-marginal units that flip with any numerical change (E0).
- Experiment (analysis of stored data, no run): split the FP-failed units by the mentor's FP result (it differs from ours only by numerical stack, E0). If (b), rows solve far more of the units the mentor's FP solves.
- Result: 64 of the 382 are solved by the mentor's FP; the five main rows solve 48.4, 48.4, 53.1, 48.4, 31.2% of them against 12.9, 15.7, 13.2, 11.6, 9.1% of the 318 that both FPs fail; the mentor's FP solves 5 of the 9 all-rows units.
- Verdict: (b) CONFIRMED for most of the gains (a correlation of stored outcomes, with the mentor's FP as the control; not an intervention); (a) not needed to explain them. The remaining 9 to 16% gain rate on units both FPs fail is of the order of the E0 flip rate and is not read as an effect.
