# S6: shrink coefficient c per tensor, 2-bit Bridge methods (CPU only)

Script: s6.py. Data: s6.json (per tensor values and summaries). c = <E,W>/<W,W>, E = Wq - W, W = FP Bridge (s5bq/checkpoints/bridge). rel = ||E||/||W||. orth = ||E - cW||/||W||.

## What exists on disk
- QuIP#: full Bridge checkpoint s5bq/ckpt/quip_w2/bridge (432 keys). Used for all 432.
- AQLM: Bridge checkpoint deleted. No Bridge head weights remain (q/aqlm_w2 has backbone and libero heads only; head_bridge dir missing).
  The backbone is read from q/aqlm_w2/backbone/*.safetensors (key "weight", dequantised, 216 tensors).
  Action head: only aqlm_w2_error.json (err_rms, w_rms, err_mean). It gives rel = err_rms/w_rms, but NOT c. So c for the AQLM head is unknown.
- QTIP: Bridge checkpoint deleted. Backbone from q/qtip_w2/backbone (216 tensors). Head: not available.
- VPTQ: Bridge checkpoint and layer files deleted. Nothing to compute.
- Check: q/ backbone is not bit-identical to the Bridge checkpoint backbone. For QuIP#, c differs by median 0.0003, max 0.0024; rel by median 0.0025. For AQLM, rel from q/ files vs error json differs by median 0.004, max 0.034 (26 of 216 above 0.01); means agree (0.5055 vs 0.5058). So the q/ backbone is a close proxy, not the exact tensor.

## Answer
1. AQLM shrinks MORE, not less. In the backbone c is about -0.156, three times the QuIP# / QTIP value (-0.05 to -0.06). Every backbone tensor has c more negative than -0.068, which is beyond the worst QuIP# tensor.
2. The shrink is even across attention q/k, v/o and MLP (-0.146 to -0.170). It is weaker only in the 24 embedding / merger tensors (-0.112). I find no "strong in one block type, weak in another" pattern inside the backbone.
3. Head versus backbone for AQLM: c for the head cannot be computed (no weights). The error json shows the head error is larger (rel 0.54 vs 0.51), so the head is not spared.
4. The orthogonal error is also larger: 0.48 of ||W|| for AQLM backbone against 0.33 (QTIP) and 0.39 (QuIP#). The shrink part is about 10 percent of the AQLM error energy (c^2/rel^2 = 0.156^2/0.506^2) and about 1.7 percent for QuIP#. So AQLM error is mostly not a shrink: a plain 0.95 W recipe does not describe it.

## Hypothesis (not tested)
A possible reading: the AQLM backbone is shrunk by about 16 percent, more than the best uniform shrink found on Bridge, and carries a large orthogonal error (0.48). This combination may cut spoon_on_towel (-46) while the same strong damping of the policy output may still help put_eggplant_in_basket (+25), which gains from damped behaviour. The data here cannot separate the shrink effect from the orthogonal effect. An intervention would be needed, for example AQLM weights with the shrink part removed (as in the "orth" row), or a 0.85 W backbone alone.
