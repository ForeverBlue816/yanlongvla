# Baseline implementation decisions

Decisions for the baseline rows run with this harness. Priority of sources: (1) `README.md` in this folder (the
mentor's protocol), (2) the mentor's instructions, (3) the official repository of each method. Runs, logs and results:
`~/projects/pi05-handover/runs/readme_baselines/` (`STATUS.md` has the live table).

| 9 | RTN | Asymmetric min/max, groups of 128 along the input dim, FP16 scale and b-bit zero per group. SigLIP fc2 (4304 inputs) gets a shorter last group of 80; its scale and zero are counted. | README step 2a | 2026-10-23 |
| 10 | GPTQ | README reference implementation: groups of 128, 1% damping, block 128, no act-order. | README | 2026-10-23 |
| 11 | AWQ | Per-input-channel scale s = rms(x)^α with rms(x) from diag of the shared Hessian, α on a 20-point grid, chosen by the Hessian-weighted output error tr(E H Eᵀ). Then the official `auto_clip` on the scaled weight: per output row and group of 128, clip to ±max\|w\|·(1 − i/20) for i = 0…9 and keep the range with the smallest group output error eᵀH_gg e (exact with the shared second moment; the official code samples tokens). q/k projections are not clipped, as in the official code. RTN g128 asymmetric on the clipped weight. One FP16 scale vector per layer, counted (scales are per layer, so they cannot all fold into a shared norm); clipping stores nothing extra. | README silent; official llm-awq `auto_scale` + `auto_clip` with the shared Hessian; mentor point 4 | 2026-10-24 |
| 12 | VPTQ | W2 = v4-k256-0: one 8-bit index per 4 weights (2.000 bpw) plus one FP16 256×4 codebook per layer, counted. Official `algorithm` branch at `5a8dfb9`, Hessian-weighted k-means (100 iterations, seed 0), 1% damping, no outliers, no norm or permutation. Not the official v8-k65536 (its 1 MB codebooks add ~1.28 bpw that the official accounting ignores). | Mentor point 2 | 2026-10-23 |
| 13 | AQLM | W2 = 2x8g8: two 8-bit codebooks over groups of 8 input weights (2.000 bpw), out group 1, FP16 codebooks (2×256×8, 8 KB per layer) and one FP16 scale per output row (`scale_nbits=0`, official default), all counted. Official `AQEngine.quantize` at commit `e79a896` with XTX = the shared E[xxᵀ]; official defaults (k-means init 100 iterations, Adam lr 1e-4 with 100 steps per epoch, beam size 1) and the README recipe's `relative_mse_tolerance=0.01`; `random.seed(0)` and `torch.manual_seed(0)` before each layer. No block or global fine-tuning. All widths (1152, 4304, 2048, 16384, …) are multiples of 8, so nothing is padded. The evaluated weight is decoded from the stored FP16 payload. | Mentor point 1; README step 2b; official repository | 2026-10-24 |
| 14 | QuIP#/QTIP dimensions | Randomized Hadamard transform. 1152 = 36 × 32 uses the size-36 Hadamard in QuIP#'s table (verified in `lib/utils/matmul_had.py` at `1d8f873`; every other width here is a power of two). 4304 = 16 × 269 has none: pad fc1 outputs / fc2 inputs to 4480 = 140 × 32 with zeros, quantize the padded matrix, and count the padded codes and all RHT sign vectors in the payload. | Mentor point 3; README step 2b | 2026-10-24 |
| 15 | Evaluation protocol | README: LIBERO 4 × 10 × 50 (and the 1900 column), LIBERO-Plus preregistered 1000 and the 2000 expansion, seed 7, paired bootstrap against the published rows. Plus 2000 = the Plus 1000 episodes + the 1000 added units (same units and seeds); the added 1000 are also reported separately, as the expansion file asks. | README | 2026-10-23 |
| 16 | Splitting evaluation | Plus in 250-unit parts, LIBERO one part per suite, packed into 12-hour PBS jobs (~11 h estimated work each). Episode outcomes do not depend on the split: seeds are set per unit and per episode. | Fit the 12 h walltime; resumable | 2026-10-23 |
| 17 | Sanity gate | Before a row's full evaluation: checkpoint structure check (embedding, exactly 414 layers changed, finite) and a 100-episode sample (50 LIBERO spatial + 50 Plus units, kept out of the results). A row with 0 successes, or ≤5% while the reference succeeds on ≥50% of the same episodes, is stopped and gets a debug job. The same rule runs on the full evaluation. | Fast feedback; user instruction | 2026-10-23 |
| 18 | RTN W2 | Stopped as a genuine collapse: 0/292 episodes (reference 248). Identity checkpoint and FP closed loop exact; RTN W3/W4 near FP; 2-bit RTN action error 1.38 (language model alone 0.76, SigLIP 0.19, expert 0.012). | Debug job `debug/rtn_w2_20261023_1849` | 2026-10-23 |
| 20 | AQLM build in parallel | Per-layer time grows steeply with the input width: 48-59 s for the expert down_proj (4096 inputs), 1.9 h for LM layer 0 down_proj (16384 inputs; relative output error 3.1e-3), about 45 GPU-hours for all 414 layers (18 LM down_proj layers dominate), so the build takes several 12-hour jobs. Four build-helper jobs quantize layers side by side, each claiming a layer by a lock file; a helper stopped by the walltime is resubmitted without counting as a failure (its finished layers are kept). The job that finds all 414 layers done writes `accounting.json`; only then is the sanity part submitted, which imports, checks and samples the checkpoint. Results do not depend on which job quantized a layer (per-layer seeds). | Fast feedback (LOOP.md); layer tests 4065133/4066001 | 2026-10-24 |

| 22 | QuIP# | W2 = E8P12: one 16-bit lattice index per 8 weights (2.000 bpw), stored packed four to an int64 as the official code does. Official `lib/algo/quip.py:quantize` at commit `1d8f873` on the shared Hessian, regularized as the official `quantize_linear` (divide by mean diagonal, +0.01 on the diagonal); official 2-bit recipe `--codebook E8P12 --scale_override 0.9` and script defaults (Hadamard incoherence, no low-rank, `quip_tune_iters` 10); `torch.manual_seed(0)` per layer for the random signs. No fine-tuning. Payload: packed indices incl. padding, FP16 `SU` and `SV` sign vectors per layer (scales fused into `SV`, official layout), and the shared E8P12 table once. SigLIP fc1/fc2 padded from 4304 to 4480 (decision 14). Needs the compiled `quiptools_cuda` / `fast_hadamard_transform` from the external-toolkit env with the gcc-12 runtime on `LD_LIBRARY_PATH`. | Mentor point 3; README step 2b; official repository | 2026-10-24 |
| 23 | QTIP | W2 = bitshift trellis, official 2-bit recipe (`example.sh`): L 16, K 2 (2 trellis bits per weight), V 2, 16×16 tiles, `quantlut_sym` with a 9-bit lookup table, `scale_override 0.9`, `sigma_reg 0.01`. Official per-layer steps of `quantize_finetune_decoder_layer` at commit `e90c668` (random signs, Hadamard incoherence, block LDL, LDLQ, `pack_trellis`) on the shared Hessian; the layer and end-to-end fine-tuning that follow in the official script are not run. Payload per layer: packed trellis incl. padding, FP16 `SU`/`SV`, FP32 `Wscale`, FP16 512×2 lookup table (all saved by the official code). Same 4304→4480 padding as QuIP#. The evaluated weight is the inverse incoherence transform of QTIP's reconstruction; the job checks the transform round trip on the unquantized weight. | Mentor point 3 (optional extra); README step 2b; official repository | 2026-10-24 |
| 24 | Hessian damping for AQLM | Add 1% of the mean diagonal to XTX before `AQEngine.quantize` (the official code adds none). Our Hessians come from 256 observations and are far from full rank (expert layer 0 down_proj: 277 eigenvalues above 1e-6 of the largest, of 4096; LM layer 0 down_proj: 3308 of 16384). Undamped, the layer test gave expert down_proj a relative weight error of 0.86 at output error 2e-5: the codes drift freely in the null space, which other inputs at evaluation time would expose. 1% is GPTQ's percdamp, already used by GPTQ and VPTQ; QuIP#/QTIP use their own `sigma_reg` 0.01. Re-tested on two layers before enabling the row. | Layer test 4065133; consistency with the other Hessian methods | 2026-10-24 |
| 25 | QuIP#/QTIP layer test | Test 4066001 on expert L0 down_proj, LM L0 k_proj and both padded SigLIP L0 MLP layers: payloads match 2.000 bpw plus counted signs, scales and tables (padded fc1/fc2: 1,301,504 B QuIP#, 1,303,556 B QTIP); QTIP transform round trip max error 2e-7. Output error (relative, on the shared H): QuIP# 2.0e-4 / 3.2e-3 / 1.1e-3 / 7.4e-4, QTIP 5.7e-5 / 9.8e-4 / 9.4e-4 / 5.5e-4. QuIP#'s relative weight error exceeds 1 on expert down_proj (1.19): our code matches the official `quantize_linear` + `quip.quantize`, and the 10 tuning sweeps act on the low-rank H, so weights move in directions the calibration does not see. Kept as the official method; the sanity sample judges it. Rows enabled with the sanity gate. | Layer test; source priority (3) | 2026-10-24 |
